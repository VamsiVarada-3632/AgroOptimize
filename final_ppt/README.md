## What the screenshots show that you should know before presenting

These are real behaviours of the current code, not capture problems:

1. **Official data only.** Every district, season and crop comes from `GET /api/catalog` (38 districts, Kharif and Rabi). Values the official datasets do not publish read "Official Data Not Available"; the weather card on Home says so with the reason (no official IMD weather feed is loaded), and the fertiliser-cost lever in Scenario Simulation is shown as unavailable.
2. **One fuzzy model everywhere.** Run Optimization now preselects the backend default `official` model, so the UI run in screenshots 07–08c gives the same recommendation as the pipeline snapshot and graphs: ragi 82.5 %, green gram 17.5 %, TOPSIS 0.6398.
3. **The illustration on the landing page is empty** in `01_homepage_onboarding.png`. The image is hosted on `lh3.googleusercontent.com`, which was not reachable from the capture machine. Re-run `capture_screenshots.py` on a network that reaches it to get that picture.
4. Full-page captures of very tall pages (14, 16) show the sticky sidebar part-way down the page; use the `b` crops on slides.
5. Some sentences generated by the backend still say "irrigation water" or "Low water use"; the objective they describe is the irrigated area.

## Regenerating everything

From the repository root, with the official database built (`python scripts/preprocess_all.py`):

```bash
python final_ppt/assets/scripts/run_pipeline_snapshot.py
python final_ppt/assets/scripts/make_graphs.py
python final_ppt/assets/scripts/make_diagrams.py
python final_ppt/assets/scripts/make_pipeline_snapshot.py
python final_ppt/assets/scripts/render_assets.py final_ppt/diagrams/methodology.svg \
    final_ppt/diagrams/module_interaction.svg final_ppt/diagrams/pipeline_execution.html   # needs playwright
# screenshots: see the header of capture_screenshots.py (local frontend build + backend on :8000)
```

Each script overwrites its outputs in place; none deletes files.
